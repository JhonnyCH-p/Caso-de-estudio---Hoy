📦  Opción 1: Fetch (Nativo de JavaScript)
¿Qué es Fetch?
FETCH es la API NATIVA de JavaScript para hacer peticiones HTTP.
Está integrada en todos los navegadores modernos.
NO necesita instalación.
Sintaxis Básica
// 📁  Ejemplo básico con fetch
// GET - Obtener datos
fetch('http://localhost:3000/api/employees')
    .then(response => response.json())  // ← Convertir a JSON
    .then(data => console.log(data))    // ← Usar los datos
    .catch(error => console.error(error));
// POST - Enviar datos
fetch('http://localhost:3000/api/employees', {
    method: 'POST',
    headers: {
        'Content-Type': 'application/json',
    },
    body: JSON.stringify({
        cedula: '1234567890',
        nombres: 'Ana García',
        salario: 1500
    })
})
    .then(response => response.json())
    .then(data => console.log(data))
    .catch(error => console.error(error));

Ventajas de Fetch
✅  NO requiere instalación (es nativo)
✅  Está disponible en todos los navegadores modernos
✅  Promesas nativas (async/await)
✅  Ligero (sin dependencias externas)
Desventajas de Fetch

📦  Opción 2: Axios (Librería Externa)
¿Qué es Axios?
AXIOS es una librería externa para hacer peticiones HTTP.
Se instala con npm.
Ofrece una API más SIMPLE y PODEROSA que fetch.
Instalación
npm install axios
Sintaxis Básica
// 📁  Ejemplo básico con axios
import axios from 'axios';
// GET - Obtener datos
axios.get('http://localhost:3000/api/employees')
    .then(response => console.log(response.data))  // ← data ya está parseada
    .catch(error => console.error(error));
// POST - Enviar datos
axios.post('http://localhost:3000/api/employees', {
    cedula: '1234567890',
    nombres: 'Ana García',
    salario: 1500
})
    .then(response => console.log(response.data))
    .catch(error => console.error(error));

const API_BASE_URL = import.meta.env.VITE_API_URL || 'http://localhost:3000';

    baseURL: API_BASE_URL,      // ← URL base

// ✅  Interceptor de REQUEST (log de peticiones)
apiClient.interceptors.request.use((config) => {
    console.log(`📡  ${config.method?.toUpperCase()} ${config.url}`);
    return config;
});
// ✅  Interceptor de RESPONSE (log de respuestas + manejo de errores)
apiClient.interceptors.response.use(
    (response) => {
        console.log(`✅  ${response.status} ${response.config.url}`);
        return response;
    },
    (error) => {
        console.error(`❌  Error: ${error.message}`);
        return Promise.reject(error);
    }
);

🎓  Preguntas de Reflexión
1. ¿Por qué axios es más popular que fetch en proyectos grandes?
   → Porque ofrece interceptores, timeout, mejor manejo de errores.
2. ¿Qué son los interceptores y por qué son útiles?
   → Son funciones que se ejecutan antes/después de cada petición.
   → Útiles para: autenticación, logging, manejo global de errores.
3. ¿Por qué el timeout es importante?
   → Para evitar que la aplicación se quede "colgada" esperando una respuesta.
4. ¿Qué pasaría si usas fetch en un proyecto grande?
   → Tendrías que escribir mucho código repetitivo para:
      - Manejar errores
      - Parsear JSON
      - Configurar headers
      - Timeout

import { useState, useEffect, useCallback } from 'react';
import { EmployeeAPI } from '../api/employee.api';
import type { Employee } from '../types/employee.types';
/**
 * Extrae un mensaje de error de forma segura
 */
function getErrorMessage(error: unknown): string {
    if (typeof error === 'object' && error !== null) {
        const err = error as { response?: { data?: { error?: string; message?: string } } };
        if (err.response?.data?.error) return err.response.data.error;
        if (err.response?.data?.message) return err.response.data.message;
    }
    if (error instanceof Error) return error.message;
    if (typeof error === 'string') return error;
    return 'Ocurrió un error inesperado';
}
